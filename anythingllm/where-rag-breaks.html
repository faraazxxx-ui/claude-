Your documents and your question have to meet in one place. Seven things can stop the meeting. This finds which one.

The seven fixes

In order of yield. Stop when it works.

1

Uploading is not embedding

The file picker holds files. The workspace holds knowledge. A file sitting in the picker is invisible to the model. You have to move it across.

workspace ▸ upload icon ▸ add file ▸ select it ▸ Move to Workspace
then wait for embedding to finish

Confirm it. Ask something you know is in the file, then click the citations under the answer. No citations means nothing was retrieved.

2

The gate is closed

Three settings decide what survives the match. All three live in one panel. Defaults are conservative — they throw away good material.

hover workspace ▸ ⚙ ▸ Vector Database
Document Similarity Threshold → No restriction
Search Preference → Accuracy Optimized
Max Context Snippets → 4–6

Threshold cuts by score: Low ≥ .25 · Medium ≥ .50 · High ≥ .75. Real answers routinely score under .50. Accuracy Optimized adds a reranking pass — slower, much better. On very large workspaces it can hang; drop back if it does.

3

Your chunks are too small to hold an idea

The embedder sets a hard ceiling on chunk size — raise the chunk slider past it and it is silently clamped back. The built-in default caps at 1,000 characters. A clinical paragraph does not fit in 1,000 characters.

Settings ▸ Embedder ▸ AnythingLLM Embedder ▸ model → nomic-embed-text-v1
then re-embed everything

The ceiling, in characters source-verified — all-MiniLM-L6-v2: 1,000 · multilingual-e5-small: 1,000 · nomic-embed-text-v1: 16,000. Sixteen times the room per chunk. Slower to embed, and worth it.

4

Wrong chat mode

Three modes, three different contracts. Picking the wrong one looks exactly like broken retrieval.

Query — documents only. Says “no relevant information found” rather than guess.
Chat — documents plus what the model already knows. This is where invention comes from.
Agent — can use tools. Recent versions default here.

Diagnostic use. Switch to Query. If the answer disappears, it was never in your documents — the model was filling in. That is a retrieval finding, not a model failure.

5

You asked RAG to do something RAG cannot do

Retrieval fetches pieces. “Summarize this whole paper” needs the whole thing. It will always disappoint, no matter how you tune it.

whole-document work → attach or pin
find-the-fact work → embed

The three methods are genuinely different tools — see below.

6

You changed the embedder or the vector database

Both are system-wide, not per-workspace. Old vectors were written by the old model in the old shape. They do not convert. They just sit there, unmatched.

delete every document from every workspace
then re-embed from scratch

So decide on day one. Changing later is not a settings change — it is a rebuild.

7

fetch failed

The built-in embedder is downloaded on first use. This error means it could not be fetched or could not run. Three causes, in order of likelihood.

1 — network blocks huggingface.co · api.huggingface.co · cdn.anythingllm.com
2 — Windows missing Visual C++ Redistributable v14.x
3 — CPU lacks AVX2 (LanceDB needs it)

Hospital networks and corporate VPNs cause the first one constantly. Test on a home connection before assuming the software is broken.

Three ways to put a document in front of the model

Choosing wrongly here is not a bug. It feels like one.

Drag into the chat box

Attach

Nothing is chunked. The model sees the full text, if it fits in the context window. Gone when the thread ends.

Use for: one paper, read once, right now.

Move to Workspace

Embed

Split, vectorised, searchable. Permanent, and shared by everyone in the workspace. This is RAG.

Use for: a library you will question again and again.

Pin icon, after embedding

Pin

Full text injected on every single turn. Skipped by search so it is not counted twice. Burns tokens hard.

Use for: the one protocol that must always be in the room.

If you are starting clean

Twenty minutes. Do them in this order — steps 3 and 4 are expensive to redo.

  1. Install DesktopOne person, private, simplest. Docker only if you need accounts and permissions.
  2. Pick a modelCloud key for quality. Ollama or LM Studio if nothing may leave the machine.
  3. Pick the embeddernomic-embed-text-v1. Changing this later means re-embedding everything.
  4. One workspace per subjectNot one for everything. Retrieval quality falls as the haystack grows.
  5. Move files inUpload, select, Move to Workspace, wait for the count to finish.
  6. Open the gate⚙ ▸ Vector Database. Threshold No restriction, Search Accuracy Optimized.
  7. Test with a known answerAsk something you can verify, then open the citations. Trust nothing until you have.

Two traps worth knowing before you hit them

Cloud will let you crash it

The hosted built-in embedder will not stop you feeding it a 5,000-page PDF — it will accept the job and take the instance down with it. Split large files, or embed on Desktop.

Bigger workspace, worse answers

Retrieval competes. Every unrelated document you add is another candidate crowding out the right one. Split by subject early; it is the cheapest quality gain available.
