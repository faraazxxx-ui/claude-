## 7. Decision

- [ ] **Stop** — completion test passed
- [ ] **Continue once** — one named weakness remains: ______
- [ ] **Restart** — the outcome itself changed; revision is the wrong operation

**Rules:**
1. Continue only if §5 names a defect. "Could be tighter" is a mood.
2. Stop when the next edit would only change wording — *stop when the next revision won't change management.*
3. After **two** failed corrections on the same point, **Restart**. Don't attempt a third. A fresh prompt containing what you learned beats a long thread of failed fixes.

⚠️ **A reviewer asked to find gaps will always find gaps.** Criticism arriving is not evidence the work is unfinished. Judge against §2, never against whether critique exists.

# Standing preferences

*Paste once per project. Keep it to one page — an over-long standing file gets ignored, which recreates the problem it solves. For each line ask: "would removing this cause a mistake?" If not, cut it.*

```
STANDING PREFERENCES

Format
- Answer first: conclusion up top, support below.
- One compact comparison table when weighing options.
- Brief "why this works" after significant choices (max 2 sentences each).
- Plain English. Define any technical term on first use.

Evidence
- Cite sources with publication dates.
- Never attribute a claim beyond what the source actually says.
- Flag disputed or informal terminology as such.
- Confidence as high/medium/low with a reason — never a decimal.

Safety
- Never put real SSN, EIN, or home address in a deliverable. Use [PLACEHOLDER].
- Failure protocol: if something can't be resolved, state what was found,
  what's unknown, and what I need to provide. Do not fill the gap.

Voice
- Use outcome verbs ("produce", "draft"), not cognitive verbs ("analyze",
  "think about").
- Match my speaking register. Don't sell me a framework.

Loop
- Draft short first. Then grade yourself on Vulnerability / Ambiguity /
  Inefficiency and fix only what fails.
- If nothing fails, say "passes" and stop.
- Don't survey best practices unless a specific gap requires it — name the gap.
```

# The five-stage loop, on one line each

1. **Define** — outcome + "Done when"
2. **Attempt** — short first draft
3. **Evaluate** — against §4, not against vibes
4. **Revise** — only named failures
5. **Decide** — Stop / Continue once / Restart
